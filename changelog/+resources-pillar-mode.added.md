Resources subsystem now supports declarative pillar-only inventory. Requires Salt >= 3008.0 (the resources subsystem under `salt.utils.resources` ships in 3008; the plug-in stays dormant on 3006/3007). The `kubernetes` resource type accepts a `resources:` list in its pillar block (e.g. `[{kind: deployment, namespace: prod, name: web}, ...]`) which is returned verbatim from `discover()` — no API call is made. Useful for air-gapped clusters, strict-RBAC scenarios where the discovery user lacks `list` permission, bootstrap workflows that declare resources before they exist, and avoiding discovery cost on busy clusters. Pillar key `mode:` (one of `discover`, `pillar`, `merge`) makes the precedence explicit; when omitted, `pillar` is inferred from the presence of `resources:`, otherwise `discover`. In `merge` mode the declared list is unioned with API-discovered IDs. Also adds the previously-missing `node` and `custom_resource_definition` kinds to the registry, fixes typos in `_DEFAULT_KINDS` (`stateful_set`→`statefulset`, `daemon_set`→`daemonset`) that silently disabled discovery for those kinds, and expands `_DEFAULT_KINDS` to cover the typed first-class kind set so users get useful out-of-box discovery without explicit pillar opt-in.
